# Changelog

All notable changes to AgoraLar are documented in this file.

Format based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

Продукт ответвлён от шаблона BaseLar v0.7.4; историю шаблона см. в BaseLar.

## [Unreleased]

## [0.22.0] - 2026-11-27

### Added

- **Ревизии в продукте**: ядро 0.13.x, контракт **6**. `upsert` принимает
  `expected_rev` (0 — создать, N — изменить N), несовпадение — `CONFLICT`
  без записи; ревизию ставит бэкенд. `ETag` в HTTP строится из содержимого
  объекта и меняется вместе с ним.
- **`bulk_patch`** (`beta`): пакетная правка фасетов — `set`/`add`/`unset`,
  по одной ревизии на объект, конфликты сообщаются пообъектно (в отличие
  от атомарной пачки импорта). Фасеты, которыми владеет источник
  (`owners=source`), не перезаписываются: их вернёт `sync`.

### Changed

- Плагины объявляют `requires_contract >=6,<7`, диапазон ядра —
  `axislar-core>=0.13,<0.14`. `sqlite`-стор считает ревизию сам (читает
  текущий документ), `json` делегирует движку.
- Патч-версии плагинов: `store_json` 0.5.5, `store_sqlite` 0.4.5,
  `source_filesystem` 0.3.5, `source_http` 0.2.5, `source_sql` 0.2.5,
  `source_markdown` 0.1.1, `analyzer_text` 0.1.5.

## [0.21.1] - 2026-11-27

### Changed

- **Фильтры в UI — чипы, состояние в адресе страницы.** Синтаксис
  `axis:op=…` больше не нужно держать в голове между запросами: фильтры
  добавляются и снимаются чипами, а выборка целиком (`f`, `limit`,
  `offset`) живёт в query string. Ссылку можно переслать, страницу
  перезагрузить, кнопка «назад» возвращает предыдущее состояние
  (`popstate`).

## [0.21.0] - 2026-11-27

### Added

- **Локальный UI, только чтение** (ADR-0019): статика без сборки и без
  внешних зависимостей, отдаётся тем же сервером (`GET /`, `/static/*`).
  Список объектов с фильтрами `axis:op=…` и пагинацией, карточка с JSON и
  связями (входящие и исходящие), таблица разреженности по осям с
  предупреждением о пустых. Loopback, без токена: read-only.
- **API v1** (`/api/v1`): `objects` (фильтры, `offset/limit`), `objects/{id}`
  с `ETag`/`If-None-Match` (304), `objects/{id}/links`, `stats`,
  `artifacts/{hash}`. Ошибки в машинно-читаемой форме
  `{"error": {"code", "message", "axis"}}`. Старые маршруты не тронуты.
- **Use-cases в beta**: `list_objects`, `entity_links`, `store_stats`;
  разбор фильтров вынесен в `iota.parse_filter` — один синтаксис для CLI
  и HTTP. HTTP-маршруты v1 стали тонкими адаптерами.

### Changed

- `Response` HTTP-слоя допускает заголовки (`ETag`); сервер отдаёт статику
  и не отдаёт файлы вне каталога статики.

## [0.20.5] - 2026-11-27

### Changed

- **Ядро ставится из PyPI**: убраны `[tool.uv.sources]` для `axislar-core`,
  шаг «скачать колесо из GitHub Release» в CI и цель `make core`. Временных
  обходов публикации больше нет — `uv sync` и CI используют индекс.
- **GitHub build provenance**: job `dist` аттестует артефакты
  (`actions/attest-build-provenance`), проверка —
  `gh attestation verify dist/*.whl --repo authorlarciss/AgoraLar`.
  Это дополнение к PEP 740 publish-аттестации, а не замена; «SLSA L3» не
  заявляем.
- **Покрытие публично**: CI кладёт HTML-отчёт артефактом `coverage-html`,
  в README появился раздел «Качество» с числами.
- `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1) и ссылка из CONTRIBUTING.

### Added

- **PEP 740 publish attestation** работает: PyPI подтверждает, что файл
  загружен workflow `ci.yml` репозитория `authorlarciss/AgoraLar`
  (environment `release`). Проверка — `/integrity/<проект>/<версия>/<файл>/provenance`.
  В `PUBLISHING.md` описаны две грабли: `sign` берёт файлы, а не каталог;
  `uv publish` цепляет sidecar только при публикации по шаблону.
  SLSA build provenance — отдельный шаг, пока не сделано (см. план).

## [0.20.1] - 2026-11-27

### Added

- **PEP 561**: `py.typed` в продукте и во всех плагинах + секции
  `[tool.setuptools.package-data]`. Раньше mypy у пользователя видел

  офлайн-вариант из колес релиза оставлен ниже.

## [0.20.0] - 2026-11-27

### Added

- **`agoralar export --format symlinks --group-by …`** (ROADMAP §3):
  дерево ссылок по значениям осей. По умолчанию dry-run; `--apply`
  создаёт симлинки, `--hardlink` — жёсткие ссылки (FS без симлинков).
  Политики: `--multi first|all|join` (по умолчанию first), bucket `_none`
  для объектов без значения, суффикс `-<id[:8]>` при коллизии имён.
  В каталог, где есть файлы не из плана, без `--force` не пишет;
  существующие ссылки не удаляет, а сообщает конфликтом. Повторный
  `--apply` идемпотентен и считает уже созданные ссылки.
  Корень файлов берётся из `--source-root` или из секции
  `[plugins.<источник>]` конфига.

## [0.19.0] - 2026-11-27

### Added

- **`agoralar visualize [--output report.html]`** (ROADMAP §7): автономный
  HTML-отчёт. По каждой оси — заполненность и распределение (top-10),
  для measurable — min/медиана/max, для скаляров — доля заполнения;
  пустые оси вынесены в предупреждение («ось неизменяема, значит либо
  забытый импорт, либо схема опередила данные»). Внизу — JSON с теми же
  данными. Ни сети, ни внешних ресурсов, ни JavaScript; все
  пользовательские строки экранируются.
- Демо теперь заканчивается отчётом: `make demo` → `report.html`.

## [0.18.0] - 2026-11-27

### Added

- **`agoralar-source-markdown` 0.1.0** (ROADMAP §4.1): источник заметок
  Markdown. Frontmatter (скаляры, `[a, b]`, блок `- item`), `#tags` в теле,
  `[[wiki-links]]` с якорем и псевдонимом; кодовые блоки игнорируются.
  Раскладка: `folder`, `tags`, `created`, `links` (reference → `note`),
  скаляры `title`, `path`, `filename`. Битая ссылка — предупреждение, а не
  теневой объект. Проходит `run_source_contract` и `run_source_sync_contract`.
- Шаблон **`obsidian-vault`** переведён на источник `markdown`:
  оси `folder`, `tags`, `created`, `links`; `sync --source markdown` уже
  даёт связи, видимые в `agoralar links`.

### Changed

- Продукт зависит от `agoralar-source-markdown>=0.1,<0.2`;
  `agoralar plugins list` показывает семь плагинов.

- Патч-версии плагинов под новый релиз: `store_json` 0.5.4,
  `store_sqlite` 0.4.4, `source_filesystem` 0.3.4, `source_http` 0.2.4,
  `source_sql` 0.2.4, `analyzer_text` 0.1.4 (код не менялся — проверка
  публикации по OIDC для каждого проекта).

## [0.17.0] - 2026-11-27

### Added

- **`agoralar init --template <имя>`** (ROADMAP §1): встроенные шаблоны
  `video-archive` и `obsidian-vault` создают `agoralar.toml` (store, секции
  `[plugins.*]`) и оси/скаляры в хранилище. Шаблон не создаёт объектов.
  Повторный запуск без `--force` отказывает, с `--force` добавляет только
  недостающее: оси неизменяемы (DOMAIN A4). `agoralar init --list`.
- **`agoralar links --id ... [--axis] [--include-deleted] [--json]`**:
  обратные ссылки через порт `IReferenceIndex`.
- **Демо-стенд** `examples/demo` + `make demo` и e2e-тест: шаблон →
  `sync --apply` → запрос → карточка → `links`. Дерево файлов источника
  не меняется, внешние сервисы не нужны.
- `render_config` пишет массивы (`levels`, `suffixes`) — параметры
  плагинов-источников в конфиге больше не нужно кодировать строкой.

## [0.16.0] - 2026-11-27

### Changed

- **`store_sqlite` стал самостоятельным бэкендом на SQL** (формат 2 не
  менялся): `get`, `fetch_many`, `count`, `list_entities`, `query` и
  артефакты читаются прямо из базы, объекты в память целиком не
  загружаются. Раньше стор был обёрткой над in-memory движком ядра и
  поднимал весь файл при первом обращении.
- **Запросы исполняются в SQL** по `facet_index`/`ref_index` с семантикой
  разреженности из DOMAIN §5 (`none_of` и `not_exists` истинны при
  отсутствии значения), пагинация — `LIMIT/OFFSET`, `total` — отдельным
  `COUNT`. Валидация запроса по-прежнему ядровая (`validate_query`).
- **Дифференциальный тест** сторов: случайные объекты и 80 случайных
  запросов сравниваются с эталонным `MemoryStorage` по `ids` и `total`;
  контрактные наборы ядра (`run_storage_contract`,
  `run_reference_index_contract`) проходятся целиком.
- Открытие хранилища больше не зависит от размера: 14.95 → 0.55 мс на
  1000 объектов и 65.7 → 0.56 мс на 5000; `upsert` при 5000 объектов
  0.59 → 0.39 мс.
- Патч-версии под новый код и зависимость: `store_sqlite` 0.4.3,
  `store_json` 0.5.3, `source_filesystem` 0.3.3, `source_http` 0.2.3,
  `source_sql` 0.2.3, `analyzer_text` 0.1.3.
- Ядро поднято до `axislar-core` **0.12.0**: контрактный набор
  `run_reference_index_contract` и пакетный `apply_plan` (атомарная
  пачка, ADR-0022 ядра). Зависимость продукта и пяти плагинов —
  `>=0.12,<0.13`.
- Тесты обоих сторов проверяют обход ссылок контрактным набором ядра,
  а не собственными проверками: «объявил возможность, а реализовал
  неверно» теперь ловится набором.

### Added

- **Инкрементальная запись в `sqlite`-сторе** (формат 2, `STORE_VERSION=2`):
  `_flush` пишет только объекты, изменённые с прошлого вызова, и пересобирает
  индексные строки только для них. Раньше каждая запись удаляла и заново
  вставляла всю таблицу (`DELETE FROM entities` + полная вставка).
- **Индексы в `sqlite`-сторе**: `facet_index(axis, value, num, entity_id)` и
  `ref_index(axis, target_id, entity_id)` с индексами по `axis`/`target_id`.
  Колонка `entities.deleted` позволяет фильтровать tombstone в SQL.
- **Миграция формата 1 → 2** при открытии: добавляется `deleted`, индексы
  пересобираются из документов, версия обновляется в той же транзакции.
- **Обход ссылок через SQL**: `references_to` в `sqlite`-сторе читает
  `ref_index` и не загружает все документы в память; файл формата 1
  мигрируется, для отсутствующего файла ничего не создаётся.
- `scripts/bench.py` и `make bench` (`BACKEND=sqlite|json`, `N=объектов`):
  запись, обновление, чтение по `id`, запрос по оси, обход ссылок,
  переоткрытие. Числа — в README.

### Changed

- `capabilities()` в `JsonStore`/`SqliteStore` кэширует набор: раньше
  каждый вызов собирал новый `build_core()`.
- Документация приведена к факту: установка из релиза `v0.11.0`/`v0.15.0`,
  статус ядра, «не цели» про Web UI (SPA/сессии запрещены, локальный
  read-only вьюер — нет), пункт про пакетный `apply_plan` (это правка
  ядра без смены контракта, не продукта).
- В план добавлен пункт 19 — инкрементальная запись и индексы в сторах
  (главный технический долг: сейчас `_flush` переписывает всё).

## [0.15.0] - 2026-11-27

### Added

- **Обратные ссылки в сторах** (ядро 0.11, ADR-0021 ядра):
  `JsonStore` и `SqliteStore` реализуют порт `IReferenceIndex` и
  объявляют `Capability.TRAVERSE_REFERENCES`; обход делегируется
  обратному индексу эталонного движка, запись/чтение остаются через
  него же. Граф связей и «на кого ссылается» больше не требуют полного
  скана в продукте.
- Зависимость от ядра поднята до `axislar-core>=0.11,<0.12` (продукт и
  пять плагинов); контракт ядра не менялся — остаётся 5.

### Changed

- Патч-версии плагинов под новую зависимость: `store_json` 0.5.2,
  `store_sqlite` 0.4.2, `source_filesystem` 0.3.2, `source_http` 0.2.2,
  `source_sql` 0.2.2, `analyzer_text` 0.1.2 (пересборка под ядро 0.11,
  код анализатора не менялся).

## [0.14.0] - 2025-11-25

### Added

- **Анализаторы как плагины продукта** (ADR-0018): вид
  `PluginKind.ANALYZER` и entry point `agoralar.analyzer`; контракт
  структурный (`IAnalyzer`: `version`, `describe`, `accepts`, `analyze`),
  поэтому плагин не импортирует ни ядро, ни продукт.
- `agoralar analyze --analyzer text [--input-role original]
  [--output-role preview] [--option k=v] [--force] [--apply]`: берёт
  входной артефакт, кладёт производный (`put_artifact`, дедупликация по
  хэшу) и обновляет объект ссылкой с `derived_by`. Dry run по умолчанию,
  повторный прогон ничего не пересчитывает.
- Плагин **`agoralar-analyzer-text` 0.1.0**: предпросмотр текста
  (обрезка по символам, UTF-8 с `errors="replace"`), без внешних
  зависимостей.

### Fixed

- `plugins/store_json` 0.5.0 понимает формат **2**: `Artifact` сериализуется
  base64url (ядро 0.9.1), бинарные артефакты больше не ломают запись.
  Файл версии 1 читается, только если в нём нет артефактов; иначе —
  понятная ошибка с требованием переимпорта.

## [0.13.0] - 2025-11-25

### Added

- **Аутентификация HTTP** (ADR-0017): bearer-токен из `--token` или
  `AGORALAR_TOKEN`, сравнение `secrets.compare_digest`. Без токена —
  локальный режим; `serve` на не-loopback адресе без токена отказывает
  (код 2), а не предупреждает. `/health` открыт как проба живости,
  остальные маршруты (включая `/plugins`, `/artifacts`) требуют токена.
- **Контейнер**: `Dockerfile` ставит только wheel (ядро, продукт,
  плагины) плюс `pydantic`/`packaging`, работает от непривилегированного
  пользователя, данные — в томе `/data`. `make docker-context` собирает
  контекст из артефактов, `make docker-build` — образ.

## [0.12.0] - 2025-11-25

### Added

  <файл> --media-type`, `get <hash> [--out]`, `ls [--json]`, `rm <hash>`;
  `put --artifact role=hash` привязывает артефакт к объекту (метаданные

- HTTP: `GET /artifacts`, `POST /artifacts` (base64), `GET /artifacts/{hash}`,

  ссылается объект).
- `plugins/store_json` 0.4.0 и `plugins/store_sqlite` 0.4.0 сохраняют
  артефакты рядом с объектами (ключ `artifacts` в файле; таблица
  `artifacts(hash, media_type, data BLOB)`).

### Changed

- **Ядро 0.9.0, контракт 5**: `CORE_CONTRACT_RANGE = ">=5,<6"`, все
  плагины объявляют `requires_contract >=5,<6` (`filesystem` 0.3.0,

## [0.11.0] - 2025-11-25

### Added

- **Плагин-источник `http`** (`agoralar-source-http` 0.1.0): JSON-массив
  записей по URL → объекты. Путь к массиву — `items` (`data.items`), поля
  раскладываются теми же `key`/`axes`/`multi`/`measurable`/`reference`/
  `scalars`/`hash`, что у `sql` (ADR-0016). `null` = отсутствие значения,
  `content_hash` — по сопоставленным полям, транспорт только читает.
  Ошибки транспорта — `HttpSourceError` (`RuntimeError`), прогон падает
  целиком. Проходит `run_source_sync_contract`.

## [0.10.0] - 2025-11-25

### Added

- **Параметры плагина-источника: конфиг и `--option`** (ADR-0015).
  `sync`/`watch` берут настройки из `[plugins.<имя>]`, явные флаги их
  уточняют, `--option KEY=VALUE` перекрывает всё. Значение разбирается как
  TOML-скаляр (`true`, `42`, `["a","b"]`), иначе остаётся строкой. Продукт
  больше не перечисляет чужие параметры: новый источник подключается без
  правок CLI.
- **Плагин-источник `sql`** (`agoralar-source-sql` 0.1.0): таблица или
  `SELECT` в sqlite → объекты. Колонки раскладываются по осям явно
  (`axes`, `multi`, `measurable`, `reference`, `scalars`), `NULL` = нет
  значения (разреженность, ADR-0010 ядра), `content_hash` — по
  сопоставленным колонкам, `id` — по `entity_id_for(source_id, key)`.
  База открывается только на чтение. Проходит `run_source_sync_contract`.
- В выводе `sync` печатается `describe()` источника.

### Changed

- `Config.source_options_for(name)` — секция плагина-источника без
  подстановки общего `data` (это путь хранилища, а не источника).

## [0.9.0] - 2025-11-25

  фасеты (`analysis`) переиспользуются по `content_hash` (ADR-0017 ядра).

## [0.8.0] - 2025-11-25

### Added

  `POST /scalars`, `GET|PUT /objects/{id}`, `POST /query`, `GET /plugins`.

## [0.6.0] - 2025-11-25
