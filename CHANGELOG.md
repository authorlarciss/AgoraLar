# Changelog

All notable changes to AgoraLar are documented in this file.

Format based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
project adheres to [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html).

Продукт ответвлён от шаблона BaseLar v0.7.4; историю шаблона см. в BaseLar.

## [0.34.0] - 2026-11-28

### Added

- **Субграф связей** (фаза 4.1): `subgraph(roots, depth, axes, direction,
  limit)` в beta и `GET /api/v1/graph`. Без `limit` не рисуем: при упоре в
  потолок ответ несёт `truncated`.
- **Граф в UI** (4.2): панель с глубиной, направлением и фильтром по
  reference-осям; SVG без зависимостей, радиальная раскладка по BFS,
  ghost-узлы пунктиром, висячие рёбра красным, клик по узлу открывает карточку.
- `scripts/bench_graph.py` — замер раскрытия: 5k объектов sqlite, depth=1
  и depth=2 — 54 мс, лист в обе стороны — 47 мс (критерий 300 мс выполнен).

### Fixed

- Граф не врёт про отсутствующие цели: удалённый или неизвестный объект
  приходит узлом `ghost`, ребро — `dangling` (ADR-0025 ядра: висячие ссылки
  существуют после `sync`, их надо показывать).

## [0.33.0] - 2026-11-28

### Added

- **Отмена синхронизации**: `POST /api/v1/jobs/{id}/cancel` и кнопка в
  интерфейсе. Отмена кооперативная — флаг проверяется после сканирования и
  перед применением плана, потому что пачка атомарна и прерывать её на
  середине нельзя. Статус задачи становится `cancelled`.
- Тесты на пачечный откат журнала (`_undo_batch`) и `Journal.remove` —
  закрыт долг покрытия после 3.2.

### Fixed

- Задача синхронизации не может «зависнуть» в `running`: у неё всегда
  проставляется `finished_at` при завершении, отмене и падении.

## [0.32.0] - 2026-11-28

### Added

- **Синхронизация из UI** (фаза 3.5): кнопка «синхронизировать», диалог выбора
  источника, прогресс по задаче, обновление списка и статистики по завершении.
  `POST /api/v1/sync` ставит задачу в фон (`202`), `GET /api/v1/jobs/{id}`
  отдаёт `running`/`done`/`failed`, `scanned` и `applied`.
- `GET /api/v1/sources`: источники из реестра вместе с секциями
  `[plugins.<имя>]`. Параметры задаются конфигом; тело запроса их перекрывает.
- `Product` несёт секции плагинов, поэтому HTTP-слой не читает конфиг заново.

### Fixed

- Второй одновременный прогон синхронизации отклоняется (`409 sync_running`),
  неизвестный плагин — `404 unknown_plugin`, плагин не-источник — `400`.

## [0.31.0] - 2026-11-28

### Added

- **Создание и удаление объектов из UI** (фаза 3.3): кнопка «создать объект»
  (вид и скаляры по схеме), кнопка «удалить» в карточке с `If-Match`.
  Удаление идёт политикой ядра: если на объект ссылаются, `409
  reference_in_use` с осью, а не висячая ссылка; действие попадает в журнал и
  откатывается кнопкой «отменить».
- `POST /api/v1/objects` — создание (`expected_rev=0`, `201` + `ETag`).
- `DELETE /api/v1/objects/{id}` — tombstone с `If-Match` и журналом.
- `POST /api/v1/artifacts` в v1 и загрузка файла из карточки: байты кладутся в
  хранилище, ссылка `artifacts.file` записывается в объект с его ревизией.

## [0.30.1] - 2026-11-28

### Fixed

- **Ctrl+C и SIGTERM останавливают `agoralar serve`**: CLI запускает сервер
  внутри `asyncio.run`, а тот ставит `Runner._on_sigint`, который первый
  SIGINT тратит на отмену главной задачи. Задача заблокирована в
  `serve_forever()` и отмену не замечает, поэтому сигнал «проглатывался», а
  процесс жил до закрытия терминала (SIGHUP). Теперь `serve` ставит свои
  обработчики и останавливает цикл через `server.shutdown()`.
- Регрессионный тест: один SIGINT завершает сервер с кодом 0.

## [0.30.0] - 2026-11-28

### Added

- **Батч-панель в UI** (фаза 3.2): чекбоксы в списке, выбор оси, режим
  (`заменить`/`добавить`/`убрать`), значения, `force` для фасетов источника;
  результат показывает изменённые, конфликты и пропуски. Кнопка «отменить»
  вызывает `POST /api/v1/undo`.
- `POST /api/v1/patch` и `POST /api/v1/undo`: правка из UI журналируется, как
  и CLI (`journaled_patch` — один путь). Массовая операция откатывается
  целиком: записи журнала несут `batch`, `undo` снимает всю операцию.

## [0.29.0] - 2026-11-28

### Added

- **Редактор фасетов в UI** (фаза 3.1): форма строится по схеме (оси и
  скаляры), сохранение идёт через `PUT /api/v1/objects/{id}` с `If-Match` из
  `ETag` карточки. Конфликт (`409`) показывает серверное состояние и даёт
  выбор: сохранить своё поверх или взять серверное. Ошибки `422` привязаны к
  полю по `error.axis`; пустое поле означает отсутствие значения, а не пустую
  строку.
- Артефакты и владение фасетами при правке из UI сохраняются: форма меняет
  только то, что введено.

## [0.28.0] - 2026-11-28

### Changed

- **Совместимость с ядром определяется контрактом, а не минором ядра**
  (ADR-0022/0026): продукт и плагины объявляют `axislar-contract>=6,<7` и
  широкий `axislar-core>=0.15,<1`. Минор ядра больше не требует перевыпуска
  плагинов; несовместимая пара (ядро с контрактом 7 и плагин на 6) не
  разрешается pip'ом.
- `make pin-core` заменён на `make pin-contract CONTRACT=X.0.0`: поднимает
  диапазон контракта в продукте и всех плагинах, когда контракт меняется.

## [0.27.0] - 2026-11-27

### Changed

- **Архив по умолчанию живёт в sqlite** (`DEFAULT_STORE`): быстрее открытие,
  инкрементальная запись, индексы по фасетам и ссылкам. `json` остаётся в
  комплекте — он удобен для переносимого файла и отладки; эталонное
  `memory` по-прежнему доступно как `--store memory` и в библиотечном
  `build_product()` без аргументов.

### Added

- **`make pin-core CORE=X.Y.Z`** (`eta.core_pins`): поднимает диапазон
  `axislar-core` в продукте и всех плагинах и обновляет lock. Появился
  потому, что минор ядра требует синхронного bump'а семи плагинов, а руками
  это забывается (ядро 0.14.2: забыли — резолвер не смог поставить ядро).
  `--check` проверяет согласованность без записи.

## [0.26.0] - 2026-11-27

### Changed

- **Публичный модуль называется `agoralar`** (было `agora_nu`):
  `pip install agoralar` теперь даёт `import agoralar`, как и обещает имя
  дистрибутива. Внутри репозитория пакет по-прежнему `nu` — имя меняется на
  деплое (`DIST_PACKAGE`), поэтому исходники и тесты не тронуты.

### Fixed

- Долг 2.6: расхождение имени дистрибутива и модуля.

## [0.25.0] - 2026-11-27

### Added

- **`PUT /api/v1/objects/{id}`** с `If-Match` (ADR-0021): `"r<N>"` —
  ожидаемая ревизия, `*` — объект должен существовать. Несовпадение → `409`
  с текущим объектом и его `ETag`, чтобы редактор показал «моё/чужое».
- **`POST /api/v1/patch`**: `ids` или `filter`, `ops` (`set`/`add`/`unset`),
  `expected_revs`, `force`. Ответ — `changed`/`conflicts`/`skipped`/`errors`,
  те же поля, что у CLI `patch`.
- `ETag` в v1 теперь из ревизии (`"r5"`), а не хеш тела: `If-Match` обязан
  давать `expected_rev`.

### Fixed

- `bulk_patch` не пишет объект, если все операции пропущены (фасеты
  источника): ревизия больше не растёт от «пропущено», и чужой `If-Match`
  не ломается на пустой правке.

### Changed

- `If-Match` со старым хешем содержимого получит `409`: `ETag` теперь
  ревизионный. Для клиентов, привыкших к прежнему значению, это ожидаемая
  смена контракта.

## [0.24.0] - 2026-11-27

### Added

- **Политика удаления** (ADR-0025 ядра, ядро 0.14.1): откат создания идёт
  через `tombstone_entity` и отказывает, если на объект уже ссылаются
  (`reference_in_use`) — вместо висячей ссылки.
- `sync --apply` предупреждает о ссылках, ставших висячими (`collect_dangling`):
  синхронизация политику не проходит (источник — владелец фактов), но молчать
  о последствиях не должна.

### Changed

- Ядро поднято до `axislar-core>=0.14,<0.15` (контракт 6 не менялся).


## [0.23.0] - 2026-11-27

### Added

- **Журнал правок и откат** (`beta.journal`): снимки объектов «до/после»
  пишутся в `.agoralar/journal.jsonl` (ограничение длины, по умолчанию
  200 записей). Откат восстанавливает снимок с проверкой ревизии: если
  объект меняли после записи — `JournalError`, а не тихая перезапись.
  Откат создания ставит tombstone (удалять модель не умеет).
- **CLI `patch`**: `--filter`, `--set/--add/--unset`, dry-run по умолчанию,
  `--apply` пишет и журналирует. Фасеты источника по умолчанию
  пропускаются с сообщением; `--force` забирает владение (`owners=user`),
  и тогда синхронизация ось не перезаписывает.
- **CLI `undo [--steps N]`**: откат последних записей журнала; `put`
  журналируется тоже.

### Changed

- `apply_patches`/`bulk_patch` возвращают пропущенные оси (`skipped`)
  вместо молчаливого игнорирования; `bulk_patch` принимает `force`.

## [0.22.0] - 2026-11-27

### Added

- **Ревизии в продукте**: ядро 0.13.x, контракт **6**. `upsert` принимает
  `expected_rev` (0 — создать, N — изменить N), несовпадение — `CONFLICT`
  без записи; ревизию ставит бэкенд. `ETag` в HTTP строится из содержимого
  объекта и меняется вместе с ним.
- **`bulk_patch`** (`beta`): пакетная правка фасетов — `set`/`add`/`unset`,
  по одной ревизии на объект, конфликты сообщаются пообъектно (в отличие
  от атомарной пачки импорта). Фасеты, которыми владеет источник
  (`owners=source`), не перезаписываются: их вернёт `sync`.

### Changed

- Плагины объявляют `requires_contract >=6,<7`, диапазон ядра —
  `axislar-core>=0.13,<0.14`. `sqlite`-стор считает ревизию сам (читает
  текущий документ), `json` делегирует движку.
- Патч-версии плагинов: `store_json` 0.5.5, `store_sqlite` 0.4.5,
  `source_filesystem` 0.3.5, `source_http` 0.2.5, `source_sql` 0.2.5,
  `source_markdown` 0.1.1, `analyzer_text` 0.1.5.

## [0.21.1] - 2026-11-27

### Changed

- **Фильтры в UI — чипы, состояние в адресе страницы.** Синтаксис
  `axis:op=…` больше не нужно держать в голове между запросами: фильтры
  добавляются и снимаются чипами, а выборка целиком (`f`, `limit`,
  `offset`) живёт в query string. Ссылку можно переслать, страницу
  перезагрузить, кнопка «назад» возвращает предыдущее состояние
  (`popstate`).

## [0.21.0] - 2026-11-27

### Added

- **Локальный UI, только чтение** (ADR-0019): статика без сборки и без
  внешних зависимостей, отдаётся тем же сервером (`GET /`, `/static/*`).
  Список объектов с фильтрами `axis:op=…` и пагинацией, карточка с JSON и
  связями (входящие и исходящие), таблица разреженности по осям с
  предупреждением о пустых. Loopback, без токена: read-only.
- **API v1** (`/api/v1`): `objects` (фильтры, `offset/limit`), `objects/{id}`
  с `ETag`/`If-None-Match` (304), `objects/{id}/links`, `stats`,
  `artifacts/{hash}`. Ошибки в машинно-читаемой форме
  `{"error": {"code", "message", "axis"}}`. Старые маршруты не тронуты.
- **Use-cases в beta**: `list_objects`, `entity_links`, `store_stats`;
  разбор фильтров вынесен в `iota.parse_filter` — один синтаксис для CLI
  и HTTP. HTTP-маршруты v1 стали тонкими адаптерами.

### Changed

- `Response` HTTP-слоя допускает заголовки (`ETag`); сервер отдаёт статику
  и не отдаёт файлы вне каталога статики.

## [0.20.5] - 2026-11-27

- `CODE_OF_CONDUCT.md` (Contributor Covenant 2.1) и ссылка из CONTRIBUTING.

### Added

- **PEP 740 publish attestation** работает: PyPI подтверждает, что файл
  загружен workflow `ci.yml` репозитория `authorlarciss/AgoraLar`
  (environment `release`). Проверка — `/integrity/<проект>/<версия>/<файл>/provenance`.
  В `PUBLISHING.md` описаны две грабли: `sign` берёт файлы, а не каталог;
  `uv publish` цепляет sidecar только при публикации по шаблону.
  SLSA build provenance — отдельный шаг, пока не сделано (см. план).

## [0.20.1] - 2026-11-27

### Added

- **PEP 561**: `py.typed` в продукте и во всех плагинах + секции

## [0.20.0] - 2026-11-27

### Added

- **`agoralar export --format symlinks --group-by …`** (ROADMAP §3):
  дерево ссылок по значениям осей. По умолчанию dry-run; `--apply`
  создаёт симлинки, `--hardlink` — жёсткие ссылки (FS без симлинков).
  Политики: `--multi first|all|join` (по умолчанию first), bucket `_none`
  для объектов без значения, суффикс `-<id[:8]>` при коллизии имён.
  В каталог, где есть файлы не из плана, без `--force` не пишет;
  существующие ссылки не удаляет, а сообщает конфликтом. Повторный
  `--apply` идемпотентен и считает уже созданные ссылки.
  Корень файлов берётся из `--source-root` или из секции
  `[plugins.<источник>]` конфига.

## [0.19.0] - 2026-11-27

### Added

- **`agoralar visualize [--output report.html]`** (ROADMAP §7): автономный
  HTML-отчёт. По каждой оси — заполненность и распределение (top-10),
  для measurable — min/медиана/max, для скаляров — доля заполнения;
  пустые оси вынесены в предупреждение («ось неизменяема, значит либо
  забытый импорт, либо схема опередила данные»). Внизу — JSON с теми же
  данными. Ни сети, ни внешних ресурсов, ни JavaScript; все
  пользовательские строки экранируются.
- Демо теперь заканчивается отчётом: `make demo` → `report.html`.

## [0.18.0] - 2026-11-27

### Added

- **`agoralar-source-markdown` 0.1.0** (ROADMAP §4.1): источник заметок
  Markdown. Frontmatter (скаляры, `[a, b]`, блок `- item`), `#tags` в теле,
  `[[wiki-links]]` с якорем и псевдонимом; кодовые блоки игнорируются.
  Раскладка: `folder`, `tags`, `created`, `links` (reference → `note`),
  скаляры `title`, `path`, `filename`. Битая ссылка — предупреждение, а не
  теневой объект. Проходит `run_source_contract` и `run_source_sync_contract`.
- Шаблон **`obsidian-vault`** переведён на источник `markdown`:
  оси `folder`, `tags`, `created`, `links`; `sync --source markdown` уже
  даёт связи, видимые в `agoralar links`.

### Changed

- Продукт зависит от `agoralar-source-markdown>=0.1,<0.2`;
  `agoralar plugins list` показывает семь плагинов.

## [0.17.1] - 2026-11-27

### Changed

- **Публикация только по OIDC**: шаг `publish` больше не использует токен
  и `--check-url`, а пропускает версии, которые уже есть в индексе
  (проверка `/pypi/<проект>/<версия>/json`). Повторный запуск job'а и

## [0.16.0] - 2026-11-27

### Changed

- **`store_sqlite` стал самостоятельным бэкендом на SQL** (формат 2 не
  менялся): `get`, `fetch_many`, `count`, `list_entities`, `query` и
  артефакты читаются прямо из базы, объекты в память целиком не

  запросов сравниваются с эталонным `MemoryStorage` по `ids` и `total`;
  контрактные наборы ядра (`run_storage_contract`,
  `run_reference_index_contract`) проходятся целиком.
- Открытие хранилища больше не зависит от размера: 14.95 → 0.55 мс на
  1000 объектов и 65.7 → 0.56 мс на 5000; `upsert` при 5000 объектов

  а не собственными проверками: «объявил возможность, а реализовал
  неверно» теперь ловится набором.

### Added

- **Инкрементальная запись в `sqlite`-сторе** (формат 2, `STORE_VERSION=2`):
  `_flush` пишет только объекты, изменённые с прошлого вызова, и пересобирает
  индексные строки только для них. Раньше каждая запись удаляла и заново

- **Обход ссылок через SQL**: `references_to` в `sqlite`-сторе читает
  `ref_index` и не загружает все документы в память; файл формата 1
  мигрируется, для отсутствующего файла ничего не создаётся.
- `scripts/bench.py` и `make bench` (`BACKEND=sqlite|json`, `N=объектов`):
  запись, обновление, чтение по `id`, запрос по оси, обход ссылок,
  переоткрытие. Числа — в README.

### Changed

  каждый вызов собирал новый `build_core()`.
- Документация приведена к факту: установка из релиза `v0.11.0`/`v0.15.0`,
