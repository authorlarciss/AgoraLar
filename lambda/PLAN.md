# План AgoraLar (продукт)

Нормативных документов по модели здесь нет и не будет: модель описана в
ядре (`AxisLar/lambda/DOMAIN.md`). Здесь — про оболочку.

## 1. Что строим

Продукт над `axislar_core.contracts`:

1. **реестр плагинов** — находит бэкенды через entry points, проверяет
   совместимость с `CONTRACT_VERSION`, отключает несовместимые с внятной
   ошибкой;
2. **готовые бэкенды** — `JsonStore`, `SqliteStore` (простые, без
   претензий на производительность);
3. **интерфейс** — CLI (`agoralar`), позже HTTP;
4. **конфиг и состояние** — какой бэкенд активен, где данные, что включено.

## 2. Не цели

- Модель, валидация, семантика запросов — ядро.
- ORM, миграции схемы, конкурентная запись.
- Веб-UI, мобильные клиенты (только CLI, потом HTTP).
- Собственная «плагинная экосистема с песочницей»: плагины доверенные,
  проверяется только совместимость контракта.

## 3. Этапы

### P0 — идентичность и решения (выполнено)

- `README.md`, `lambda/PLAN.md`.
- ADR-0011 «реестр плагинов и версия контракта».
- Зависимость от ядра: артефакт релиза (репозиторий приватный), позже —
  PyPI-версия.

### P1 — реестр плагинов (`beta`), 1 день

- `alpha`: `PluginKind` (`storage`, `source`), `PluginManifest`
  (`name`, `kind`, `requires_contract`, `factory`).
- `beta`: `PluginRegistry` — обход `importlib.metadata.entry_points` по
  группам `agoralar.storage` / `agoralar.source`, разбор
  `requires_contract` через `packaging.specifiers`, отказ при
  несовместимости, список доступных/отклонённых с причинами.
- `psi`: `build_product(core=None, registry=None)` — собирает реестр и
  ядро с выбранным бэкендом.
- Тесты: фейковые entry points через `monkeypatch`, проверка отказов
  (`>=3` при контракте 2 → отклонён), отсутствие плагинов.

**Готово, когда:** реестр находит плагины из entry points, отказывает
несовместимым с указанием причины, покрыт тестами без установки реальных
пакетов.

### P2 — встроенный JSON-бэкенд (`delta`), 2 дня

- `JsonStore(IStorageEngine)`: схема + объекты в одном файле, атомарная
  перезапись, `capabilities()` без `REFERENCE_CHECK` (ссылки проверяются
  при загрузке).
- Контрактный набор ядра прогоняется на нём как на плагине:
  `tau/contract/test_storage_contract.py` копируется из ядра с фабрикой
  `JsonStore` (или импортируется, если ядро поставляет `contract-kit`).
- ADR-0012 при отклонениях от контракта, если появятся.

**Готово, когда:** JSON-бэкенд проходит контрактный набор целиком,
`capabilities()` честно объявляет ограничения.

### P3 — CLI (`gamma`), 1 день

- `agoralar schema add-axis|add-scalar|show`, `put`, `show`, `query`,
  `plugins list`, `store use <name>`.
- Никакой доменной логики: только разбор аргументов, вызов контрактов,
  форматирование.

**Готово, когда:** сценарий из README воспроизводится одной командой,
тесты — на разбор аргументов и формат вывода.

### P4 — конфиг и состояние (`iota` + `beta`), 1 день

- `agoralar.toml` рядом с данными: активный бэкенд, путь к файлу,
  включённые плагины.
- `build_product` читает конфиг, поднимает бэкенд из реестра.

### P5 — релиз 0.1.0

- `iota` → `nu`, bump `0.1.0`, CHANGELOG, тег `v0.1.0`, деплой через
  `make dist` (`DIST_PACKAGE=agora_nu`).

## 4. Совместимость

- Продукт объявляет `CORE_CONTRACT_RANGE = ">=2,<3"` в `mu`.
- Плагин объявляет свой `requires_contract`; продукт проверяет пересечение
  с версией ядра **и** с диапазоном продукта.
- Несовместимый плагин не отключает продукт: он попадает в список
  отклонённых с причиной.

## 5. Риски

| Риск | Признак | Что делаем |
|------|---------|------------|
| Продукт начнёт «дописывать» модель | валидация в `delta`/`gamma` | проверки только через `axislar_core.contracts` |
| Реестр превратится в плагинную платформу | манифесты, sandbox, версии API | только `requires_contract` и группы entry points |
| Приватное ядро блокирует установку | нет PyPI | до публикации — артефакт релиза; дальше — `axislar-core>=0.2,<0.3` |
| CLI потянет доменную логику | ветвления по типу оси в `gamma` | типизация по схеме остаётся в ядре |
