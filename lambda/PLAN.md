# План AgoraLar (продукт)

Нормативных документов по модели здесь нет: модель описана в ядре
(`AxisLar/lambda/DOMAIN.md`). Здесь — про оболочку.

## 0. Статус (2026-11-27)

**Текущая версия — 0.20.1** на ядре `axislar-core` 0.12.0 (contract 5).
Выполнено: P0–P5 и сверх плана — HTTP, история прогонов, периодический
`watch`, провенанс и reuse производных фактов. Плагины: `json` (0.5.4),
`sqlite` (0.4.4), `filesystem` (0.3.4), `sql` (0.2.4), `http` (0.2.4),
`markdown` (0.1.0), анализатор `text` (0.1.4) — все `requires_contract >=5,<6`.

В 0.10.0 добавлено: параметры источника из `[plugins.<имя>]` и `--option`
(ADR-0015) и плагин-источник `sql` (sqlite, только чтение; `NULL` = отсутствие
значения, `content_hash` по сопоставленным колонкам). В 0.11.0 — источник
`http`: JSON-массив записей, та же семантика раскладки и разреженности
(ADR-0016). В 0.12.0 — артефакты поверх контракта 5 ядра (ADR-0019 ядра):
CLI `artifact put/get/ls/rm`, HTTP `/artifacts`, бэкенды `json`/`sqlite`
хранят байты рядом с объектами. В 0.13.0 — HTTP с bearer-токеном и
контейнером (ADR-0017): без токена только loopback, `/health` открыт,
образ собирается из wheel. В 0.14.2 — MIT, честные зависимости
(`axislar-core` и пины плагинов), публикация репозитория и пакетов. В 0.14.0 — анализаторы как плагины (ADR-0018):
`PluginKind.ANALYZER`, `agoralar analyze`, плагин `text` 0.1.0.

## 2. Не цели

- Модель, валидация, семантика запросов — ядро.
- ORM, миграции схемы, конкурентная запись (ревизии/ETag — отдельный ADR,
  когда появится редактор).
- SPA, сессии, логин, мобильные клиенты. Локальный read-only вьюер
  (ROADMAP §4.2) — не «веб-UI» в этом смысле и не запрещён.
- Собственная плагинная платформа с песочницей: плагины доверенные.

## 3. Что дальше (по приоритету)

Критерий готовности указан у каждого пункта; подробности и грабли —
в `.dsh/NOTES.md` (раздел HANDOFF). Продуктовые направления из внешней
критики (шаблоны, экстракторы, симлинк-экспорт, markdown-источник, Web UI,
cookbook) разобраны отдельно — `lambda/ROADMAP.md`, там же очередь и
технические ограничения; ниже они сведены в общий список.

1. **Завершить публикацию в PyPI.** Опубликованы `axislar-core` 0.11.0,
   `agoralar-analyzer-text` 0.1.2, `agoralar-source-filesystem` 0.3.2,
   `agoralar-source-http` 0.2.2. Ждут лимита PyPI (4 новых проекта в
   24 часа) `agoralar` 0.15.0, `agoralar-store-json` 0.5.2,
   `agoralar-store-sqlite` 0.4.2, `agoralar-source-sql` 0.2.2 — колеса
   уже в `dist/`, публиковать с `--resume`.
   Продолжить: `scripts/publish.sh --index pypi --resume` либо Trusted
   Publishing по тегу (job `publish`, ADR-0017/CI).
   *Готово, когда* `make verify-index` проходит целиком и
   `pip install agoralar` ставит ядро и все плагины.
2. **Убрать временные обходы после публикации.** Удалить
   `[tool.uv.sources]` для ядра, шаг скачивания колеса в CI, обновить
   установку в README, отозвать bootstrap-токен.
3. **Образ в `ghcr.io`.** Job в CI с `packages: write`: сборка и публикация
   `ghcr.io/authorlarciss/agoralar:<версия>` и `:latest`.
   *Готово, когда* `docker run ghcr.io/authorlarciss/agoralar:latest`
   отвечает на `/health` без локальной сборки.
4. **Бенчмарки.** `scripts/bench.py` на 10k/100k объектов для `memory`,
   `json`, `sqlite`: запись, чтение по `id`, запрос по оси, `sync`.
   *Готово, когда* числа воспроизводимы и опубликованы в README с
   конфигурацией машины.
5. **Гайд «свой плагин».** `lambda/PLUGINS.md` + пример: контракты
   `IStorageEngine`, `IEntitySource`, `IAnalyzer`, entry points
   `agoralar.storage`/`source`/`analyzer`, `requires_contract`, контрактные
   наборы как тесты. *Готово, когда* плагин пишется по гайду без чтения
   кода продукта.
6. **Пользовательская документация — разделена на три части, и только
   одна из них делается сейчас.**
   6a. **Reference — делается всегда.** `--help`, тексты ошибок с
   подсказками, docstrings. Это не обучение, а поверхность интерфейса: она
   проверяется тестами (CLI-тесты, e2e), поэтому не гниёт.
   6b. **Quickstart в README — 10–15 строк, не больше.** Проверяется
   `make demo` и e2e-тестом, а не обещанием. Растёт только вместе с
   реальной возможностью.
   6c. **Рецепты, cookbook, туториалы — после UI.** Прозаические
   инструкции к интерфейсу, который ещё меняется, — это долг: их придётся
   переписывать, а до переписывания они врут. Точка старта — когда UI
   появится и станет понятно, что именно объяснять. *Не раньше.*
7. **`export`/`import` (JSONL).** Перенос данных между бэкендами и
   человекочитаемый бэкап (schema, entities, artifacts в base64).
8. **Потребитель M7.** `GET /features?client=web` в HTTP и `--client` в
   CLI, чтобы `resolve_feature` использовался в продукте, а не только в
   тестах ядра.
9. **Анализаторы изображений/эмбеддингов.** Тем же контрактом `IAnalyzer`;
   учесть вес образа (Pillow) и `ArtifactMismatch` при совпадении байтов.
10. **Демо-стенд** — сделано: `examples/demo` + `make demo` + e2e-тест.
    Сценарий `init → sync → query → links` за одну команду, файлы
    источника не меняются.
11. **`agoralar init --template <имя>`** — сделано: `video-archive`,
    `obsidian-vault`, `--list`, `--force`, шаблон не создаёт объектов.
12. **Пакетный импорт связей** (ROADMAP §5.1): `apply_plan` в ядре пишет
    объекты пачкой через `bulk_upsert` (ссылки проверяются по всей пачке),
    чтобы первый импорт связанных заметок не падал на `DanglingReference`.
    Правка без смены контракта и без ADR — семантика уже определена портом.
    *Готово, когда* импорт заметок со ссылками проходит с первого прогона.
13. **`agoralar-source-markdown`** — сделано (ROADMAP §4.1): frontmatter,
    `#tags`, `[[links]]` (с якорем и псевдонимом) → фасеты и reference-ось;
    битая ссылка — предупреждение, а не теневой объект; кодовые блоки
    игнорируются. Шаблон `obsidian-vault` переведён на этот источник,
    e2e-тест проверяет `sync → query → links`.
14. **`export --format symlinks --group-by …`** — сделано (ROADMAP §3):
    дерево симлинков, dry-run по умолчанию, `--multi first|all|join`,
    `_none` для разреженных, суффикс id при коллизиях, `--hardlink`,
    защита от записи в чужой каталог (по содержимому, а не по «непусто»),
    идемпотентный повтор, существующие ссылки не удаляются.
15. **`agoralar visualize`** — сделано (ROADMAP §7): автономный HTML без
    сети, ресурсов и JavaScript; заполненность и распределение по каждой
    оси, медиана/min/max для measurable, доля скаляров, пустые оси
    отдельным предупреждением, JSON-блок с теми же данными для машин.
    Пользовательские строки экранируются (тест на `<script>`).
16. **Web UI на loopback** (ROADMAP §4.2): статика в `nu/gamma/public/`,
    список/фильтры/карточка/скачивание артефакта; токен — только
    `sessionStorage` и явное предупреждение. *Готово, когда* UI работает
    на `agoralar serve` без отдельной сборки.
17. **`extractor` как вид плагина** (ROADMAP §2): байты → фасеты/скаляры с
    `owners=analysis` и `derived_by`; первый плагин — ffprobe. Требует ADR
    (продуктовый контракт) и решения по потоковому доступу к артефактам.
18. **Cookbook** (ROADMAP §6): `docs/recipes/*.md` — три первых рецепта
    (видеоархив, Obsidian, «я удалил файл»).
19. **`sqlite`-стор как самостоятельный бэкенд.** Готово: инкрементальная
    запись, `facet_index`/`ref_index`, запросы и обход ссылок в SQL,
    никакой полной загрузки, миграция формата автоматом, контрактные
    наборы ядра + дифференциальный тест против `MemoryStorage`,
    `scripts/bench.py`. Осталось (новый пункт): пушдаун `exists`/
    `none_of` через анти-джойн и кэш планов, если появятся сотни тысяч
    объектов; `json`-стор сознательно остаётся медленным.
21. **Семантический поиск и эмбеддинги — отложено, форма зафиксирована.**
    Решение — ADR-0023 ядра: близость это отдельная операция `similar_to`
    над подмножеством (`где: Query` → kNN), а не узел в `Query`; эмбеддинг —
    артефакт роли `embedding` с идентичностью модели в `derived_by`;
    индекс — порт `ISimilarityIndex` в бэкенде, первый срез — перебор,
    ANN только по замеру. Продуктовая часть, когда дойдёт очередь:
    плагин-эмбеддер (analyzer) → `agoralar search --similar-to <id>` →
    `--text` через настроенный эмбеддер. *Условие старта:* в системе есть
    реальные тексты (markdown-источник) и хотя бы один запрос «покажи
    похожее», который сейчас неудобно делать фильтрами.

20. **BotCore/HermesLar** — отдельный проект; карта в
    `VaultLar/.dsh/FUTURE-bots.md`. Профили клиентов из M7 — заготовка
    именно под него.

## 4. Риски

| Риск | Признак | Что делаем |
|------|---------|------------|
| Продукт начнёт «дописывать» модель | валидация в CLI/HTTP/бэкендах | проверки только через `axislar_core.contracts` |
| Реестр превратится в платформу | манифесты, песочница, версии API | только `requires_contract` и entry points |
| Приватное ядро блокирует установку | нет PyPI | до публикации — wheel из `AxisLar/dist` (`make core`) |
| Рассинхрон версий контракта | плагины отклоняются | контракт поднимается явно, плагины и продукт обновляются в одном проходе |
