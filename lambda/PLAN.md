## 0. Статус (2026-11-27)

**Текущая версия — 0.25.0** на ядре `axislar-core` 0.14.2 (contract 6);
продукт объявляет `CONTRACT_VERSION = 1` при диапазоне ядра `>=6,<7`.
Выполнено: P0–P5 и сверх плана — HTTP, история прогонов, периодический
`watch`, провенанс и reuse производных фактов. Плагины: `json` (0.5.6),

В 0.10.0 добавлено: параметры источника из `[plugins.<имя>]` и `--option`
(ADR-0015) и плагин-источник `sql` (sqlite, только чтение; `NULL` = отсутствие

`PluginKind.ANALYZER`, `agoralar analyze`, плагин `text` 0.1.0. В 0.22.0 —

В 0.24.0 — политика удаления (ADR-0025 ядра): откат создания отказывает при

## 2. Не цели

- Модель, валидация, семантика запросов — ядро.
- ORM, миграции схемы, конкурентная запись (ревизии/ETag — отдельный ADR,
  когда появится редактор).
- Многопользовательская работа, роли, облако, мобильные клиенты. Локальный
  UI — цель (фазы 1–5), но он однопользовательский и работает с локальными
  файлами.
- Собственная плагинная платформа с песочницей: плагины доверенные.

## 3. Порядок работ

Три принципа, из которых выведен порядок:

1. **Продукт — для человека с архивом, а не для разработчика.** Ядро и плагины
   первичны, но ценность появляется в интерфейсе: пока основная работа идёт
   через CLI, мы продаём API, а не порядок.
2. **Порядок задают зависимости, а не желания.** UI требует стабильного API и
   use-cases; редактирование требует ревизий и отката; граф требует
   работающего просмотра; упаковка требует готового интерфейса.
3. **Каждая фаза заканчивается измеримым критерием** и выпуском. Фаза, которую
   нельзя проверить на своём архиве, не считается сделанной.

### Технический долг (держим в виду, не отдельная фаза)

- `cli.py` ~900 строк и HTTP, дублирующий его логику — разбирается по мере
  надобности в 1.4, не «большим рефакторингом».
- `json`-стор переписывает файл целиком — осознанно (переносимость и диффы);
  перевод на формат 2 только при появлении реальной боли.
- Пушдаун `exists`/`none_of` анти-джойном и кэш планов — если появятся сотни
  тысяч объектов.
- Миграции схемы (deprecate/переименование осей) — после редактора, отдельный
  ADR: оси неизменяемы (DOMAIN A4), значит нужна явная операция с планом
  миграции, а не переименование «на месте».

### Осознанно не делаем

Облако и SaaS, многопользовательскую работу и роли, плагинную песочницу, ORM,
«граф» как сущность модели, векторный поиск как узел `Query`, отдельный
репозиторий для cookbook.

## 4. Риски

| Риск | Признак | Что делаем |
|------|---------|------------|
| Продукт начнёт «дописывать» модель | валидация в CLI/HTTP/бэкендах | проверки только через `axislar_core.contracts` |
| Реестр превратится в платформу | манифесты, песочница, версии API | только `requires_contract` и entry points |
| Ядро не установится из индекса | `uv sync` без сети | ядро в PyPI с 0.10.1; офлайн-путь — колеса из релиза |
| Рассинхрон версий контракта | плагины отклоняются | контракт поднимается явно, плагины и продукт обновляются в одном проходе |
