# ADR-0020: Открытие проекта — нативный выбор папки, а не правка конфига

## Статус

Принято. Реализация — фаза 5 (`lambda/PLAN.md` §3), вместе с упаковкой.

## Контекст

Сейчас «проект» — это каталог с `agoralar.toml`, а сервер обслуживает одно
хранилище, найденное вверх от текущего каталога. Для переключения между
архивами в плане стоял реестр `~/.config/agoralar/workspace.toml` и
переключатель в UI. Владелец проекта справедливо возразил: это не
пользовательский продукт. Пользователь не должен редактировать TOML,
чтобы открыть свою папку с фото, и не должен вручную запускать
синхронизацию.

Одновременно есть жёсткое техническое ограничение, из-за которого
«просто дать ввести путь в браузере» нельзя:

- браузер не отдаёт серверу реальный путь к папке; `showDirectoryPicker()`
  даёт handle внутри браузера (и только в Chromium), а не строку пути для
  бэкенда;
- если путь принимает HTTP-сервер на loopback, то его может отправить любая
  страница в браузере (`fetch` на `127.0.0.1`) — это чтение файловой
  системы мимо прав и ожиданий пользователя.

## Решение

1. **Папку выбирает человек в системном диалоге, а не вводит текстом.**
   Диалог вызывает приложение (десктоп-оболочка), путь передаётся бэкенду
   по внутреннему каналу (IPC/аргумент запуска), а не через HTTP. Это
   единственный способ получить реальный путь, не открывая дыру.
2. **Список проектов ведёт приложение, а не пользователь.** «Недавние» —
   это состояние приложения: оно пишет его само после выбора папки.
   Файл реестра остаётся деталью реализации; в интерфейсе — список
   «Открыть папку…» + недавние.
3. **`agoralar open <путь>`** — тот же сценарий без оболочки: регистрирует
   папку и открывает её. Плюс ассоциация файла-маркера `project.agoralar`
   (двойной клик из файлового менеджера) и пункт «Открыть с помощью».
4. **Папка без конфига не ошибка, а приглашение.** Открыл папку — UI
   предлагает мастер: выбрать шаблон (`video-archive`, `obsidian-vault`),
   показать превью плана синхронизации, запустить. Ручная правка TOML не
   нужна ни на одном шаге. Мастер — это те же `init --template` и `sync`,
   но экранами.
5. **Синхронизация — не кнопка, а состояние.** При открытии проекта и далее
   по расписанию (`watch`) источник синхронизируется сам; в шапке видно
   «синхронизировано 2 мин назад», при необходимости — прогресс и отмена
   через job API (пункт 3.5 плана).
6. **Веб-режим без оболочки остаётся, но с ограничениями:** список
   проектов — только из явных действий (`agoralar open`, запуск с
   `--config`), плюс обнаружение с согласием: сервер ищет `agoralar.toml` в
   известных местах (`~`, `~/Documents`, текущий каталог) и показывает
   найденное кнопкой «найти мои архивы». Путь из браузера не принимается
   никогда.
7. **Изменяющие действия на loopback защищены от чужой страницы:** проверка
   `Origin`/`Sec-Fetch-Site`, сессионный cookie с `SameSite=Strict`,
   выдаваемый при запуске, и отказ на запросы без него. Это не замена
   токену для сети (ADR-0017), а защита локального сервиса от CSRF.

## Альтернативы

- **Реестр, который правит пользователь.** Отклонено: это не продукт, это
  конфиг-файл с интерфейсом из текстового редактора.
- **Путь из браузера (`?config=...`).** Отклонено: чтение файловой системы
  по запросу любой страницы.
- **`showDirectoryPicker()` в браузере.** Даёт handle, но не путь;
  бэкенду нечего индексировать. Годится только для будущего «импорта
  файла», не для открытия архива.
- **Один сервер на все проекты с общим индексом.** Смешивает архивы и
  ломает изоляцию; кроме того, непонятно, чьи оси показывать.
- **Только CLI-открытие, без диалога.** Лучше конфига, но всё ещё требует
  терминала — для целевой аудитории это барьер.

## Последствия

Плюсы: открыть архив = выбрать папку; настройка сводится к мастеру;
синхронизация не требует действий; нет дыры с путями из браузера.

Минусы: нужна десктоп-оболочка (pywebview/Tauri), а значит упаковка под три
ОС и подпись — это вес и работа; веб-режим остаётся урезанным по удобству
(это осознанно); появляется состояние приложения (недавние проекты), которое
надо где-то хранить и мигрировать.

## Проверка

Фаза 5 считается сделанной, когда человек, получив файл приложения, может
без терминала: открыть папку с архивом, увидеть превью синхронизации,
запустить её, увидеть объекты и связи, а затем открыть вторую папку через
список недавних. Ни одного редактирования конфига по пути.
