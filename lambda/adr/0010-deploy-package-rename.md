# ADR-0010: Деплой-переименование пакета (`nu` → `<dist>_nu`)

## Контекст

В шаблоне корневой пакет называется `nu`: разработка читается как
`from nu.psi.contracts.alpha import Entity`. Это удобно, но два проекта
экосистемы не могут поставляться с одинаковым пакетом: продукт, ядро и
плагины должны ставиться в один venv, а `nu` в каждом из них — один и тот
же top-level.

Переименовывать пакет руками в репозитории нельзя: пострадает вся
документация и привычный `from nu import ...`, а также появится риск
расхождения между репозиторием и артефактом.

## Решение

Переименование выполняется **перед сборкой дистрибутива**, в копии дерева:

```
make dist                     # DIST_PACKAGE=baselar_nu по умолчанию
python -m eta.rename_package --to axislar_core --from-dir .deploy
```

`eta/rename_package.py`:

1. копирует проект в `.deploy/`, пропуская `.git`, `.venv`, кэши;
2. переименовывает каталог пакета `nu` → целевое имя;
3. переписывает токен `nu` (граница слова) в `.py`, `.pyi`, `.toml`,
   `.yaml`, `.md`, `.sh` и в `Makefile`-подобных файлах — то есть импорты,
   `include = ["nu*"]`, `root_package`, `--cov=nu`, `-m nu.main`;
4. падает, если после правки остались `from nu` / `import nu`;
5. поддерживает `--dry-run`.

Сборка идёт из `.deploy/` (`uv build`), артефакты — в `dist/`. Рабочее
дерево остаётся с пакетом `nu`.

## Альтернативы

- **Называть пакет уникально с самого начала** (`baselar_nu` в шаблоне и
  `axislar_core` в каждом проекте). Пропадает необходимость в скрипте, но
  код и документация получают длинные префиксы, а форк каждый раз требует
  ручного переименования. Отклонено.
- **PEP 420 namespace-пакет `nu` для нескольких дистрибутивов.** Работает,
  но mypy/import-linter/editable-установки ведут себя непредсказуемо, а
  смешение двух версий пакета диагностируется плохо. Отклонено.
- **Переименование вручную на релизной ветке.** Требует мержа обратно и
  гарантирует расхождения. Отклонено.

## Последствия

Плюсы: в разработке — короткое `nu`; в артефакте — уникальное имя;
переименование детерминировано и проверяемо (`leftover_imports`);
`--dry-run` показывает объём правок.

Минусы: артефакт нельзя собрать «как есть» — только через `make dist`;
`sdist` содержит уже переименованные пути, поэтому тесты в нём ссылаются на
новое имя (это правильно, но непривычно); скрипт правит текст, а не AST,
поэтому редкие строковые упоминания `nu` в прозе тоже меняются.

## Статус

Принято.
