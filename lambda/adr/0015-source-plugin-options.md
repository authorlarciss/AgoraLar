# ADR-0015: Параметры плагина-источника — конфиг плюс `--option`

## Контекст

До 0.10.0 `sync`/`watch` умели ровно один источник (`filesystem`) и знали
его параметры поименно: `--root`, `--levels`, `--code`. Каждый новый
источник (SQL, HTTP, что угодно дальше) требовал правки CLI продукта —
то есть продукт начинал перечислять чужие настройки и менялся вместе с
плагином. Это противоречит роли продукта и ADR-0011: параметры плагина —
его дело, продукт лишь передаёт их.

## Решение

1. **Источник получает ровно свою секцию конфига** —
   `Config.source_options_for(name)` → `[plugins.<name>]`. Общий `data` не
   подставляется: это путь хранилища, а не источника, и угадывать его
   смысл в чужих настройках нельзя.
2. **`--option KEY=VALUE`** (повторяемый) — универсальный канал для
   параметров, которых нет в конфиге или нужно перекрыть на один прогон.
   Значение разбирается как TOML-скаляр (`true`, `42`, `["a","b"]`,
   `"строка"`); что TOML не разобрал — остаётся строкой, поэтому
   `query=SELECT * FROM t` не требует кавычек.
3. **Порядок наложения:** секция конфига → специализированные флаги
   (`--root`, `--levels`, `--code`, `--source-id`) → `--option`. Последний
   всегда побеждает: это явное намерение пользователя здесь и сейчас.
4. **Специализированные флаги остаются** ради совместимости с 0.5–0.9 и
   коротких команд для частого случая. Они не растут: новые параметры
   идут только через `--option` и конфиг.
5. **Плагин валидирует свои параметры сам** и бросает `ValueError` с
   человекочитаемым текстом; CLI печатает его без трейсбека.

## Альтернативы

- **По флагу на каждый параметр каждого плагина.** Продукт обязан знать
  все источники и меняется при каждом новом. Отклонено.
- **Единая схема параметров в ядре** (описание опций, типы, дефолты).
  Превращает ядро в фреймворк плагинов; сейчас достаточно контракта
  `IEntitySource`. Может быть пересмотрено, если плагинов станет много и
  понадобится авто-документация.
- **Передавать плагину весь конфиг.** Плагин увидел бы чужие секреты и
  чужие настройки; границы размываются. Отклонено.

## Последствия

Плюсы: новый источник подключается без правок продукта (SQL-плагин
добавлен в этом же релизе и потребовал только `--option`); один механизм
для конфига и разового переопределения.

Минусы: `--option` не типизирован на уровне CLI (ошибку типа сообщает
плагин), нет автодополнения и `--help` по конкретным параметрам. Плата
осознанная: продукт не должен знать чужих опций.

## Статус

Принято.
