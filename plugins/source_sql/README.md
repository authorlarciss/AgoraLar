# agoralar-source-sql

Источник объектов для [AxisLar](https://github.com/authorlarciss/AxisLar):
таблица или `SELECT` в sqlite раскладывается по осям и скалярам.

Плагин продукта [AgoraLar](https://github.com/authorlarciss/AgoraLar).
База открывается **только на чтение** (`mode=ro`): источник ничего не
пишет.

```toml
[plugins.sql]
path = "/data/export.db"           # файл sqlite
table = "edits"                    # или query = "SELECT ... FROM ..."
source_id = "db-edits"             # стабильный id источника, не путь
kind = "edit"
key = ["id"]                       # естественный ключ → entity_id_for

axes = ["author", "genre"]         # категориальные оси
multi = { genre = "," }            # значения через запятую → мультизначность
measurable = ["year"]              # измеримые оси (числа)
reference = { editor = "person" }  # ссылочные оси: колонка → вид цели
scalars = ["title"]                # текстовые поля
hash = ["title", "author", "genre", "year", "editor"]   # по умолчанию — все
```

Правила:

- **`NULL` — это отсутствие значения**, а не пустое: фасет не создаётся,
  объект остаётся разреженным (ADR-0010 ядра). Скаляр с `NULL` тоже не
  пишется.
- Колонка не может быть объявлена дважды (ось и скаляр одновременно);
  `multi` допустим только для категориальных осей.
- Строка без значения в ключевой колонке пропускается с предупреждением.
- Нечисловое значение у `measurable` даёт предупреждение и пропуск фасета;
  строка импортируется.
- `content_hash` считается по каноническому JSON значений **сопоставленных**
  колонок: изменение неиспользуемой колонки не считается изменением
  объекта.
- `id` = `entity_id_for(source_id, key)`, где `key` — значения ключевых
  колонок через unit separator (`\x1f`). Переименование строки = новый
  `id`; синхронизация узнаёт переезд по `content_hash`.

Проверки плагина — `run_source_sync_contract` из ядра: тот же набор,
который обязаны проходить все источники.
